# 对拍

中文名：**对拍** · 前缀 `duet` · 端口 **7800**

## 骨架（新骨，不是闸对/缝包换皮）

**左轨装载 → 右轨装载 → 同键对齐落差 → 单边悬账 → 对拍结论**

| 对比 | 闸对 | 缝包（已弃） | **对本仓** |
| --- | --- | --- | --- |
| 拓扑 | 单流入→在途→成物 | 单流入→在途→成物 | **双轨独立装载→键对齐** |
| 在途态 | 开腿账 | 拼缝账 | **无开腿/拼缝；悬账是对齐后单边** |
| 产物 | 行程账 | 整件账 | **对齐差 + 对拍结论** |
| 旁路名 | 旁路匣 | 旁路匣 | **悬账单（命名与语义都不同）** |

皮：支付渠道回执 vs 核心记账。去皮：**双源键对齐管道**。禁止做成收银 CRUD、报表看板、工单系统。

## 页面（真翻页，每模块独立 HTML）

对拍台 · 左轨流水 · 右轨流水 · 对齐差表 · 悬账单 · 对拍结论 · 源登记 · 轨规

## 已落桩：金额容差策略（闭区间形态）

工程形态二选一定为**闭区间容差**（保基线 `<=` happy path，默认容差 0 等值仍对齐，不造旁路凭证表）：

- `|差| < 容差分` → 对齐；`|差| = 容差分`（贴边）也判**对齐**，说明里标贴边，不进悬账、`旁路凭证=null`；`|差| > 容差分` → 金额不符。
- 纯函数裁决 `app/modules/金额容差策略`；只读接口 `GET /api/容差裁决?业务键=&左金额分=&右金额分=&容差分=`（容差分留空读轨规），返业务键、左右金额、容差分、差型、贴边、`valid`、旁路凭证、形态。
- 写闸（`app/services/写闸.py`，进程锁 + `BEGIN IMMEDIATE`）：跑对齐在单事务内读轨规→清旧差→写对齐差/悬账；改容差走同一写闸，值变更时同事务作废旧差。二者互斥、同成败，不允许新旧两套差并存。
- 对拍结论加闭区间不变量：判「对齐」的键不得有悬账。
- 顺带修复基线路由缺陷：`/api/左轨/夹具/{名}` 的非 ASCII 占位符 `{名}` 被 Starlette 编译成字面量永不命中（POST 落静态挂载返 405），占位符改 ASCII `{name}`，URL 路径中文不变。
